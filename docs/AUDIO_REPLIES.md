# スーの音声返信

音声ファイル1件を、スーへのメンションまたは返信に添付してください。
「スーの独り言」ではメンションなしの音声添付にも返答します。
テキストで「@スー 声で挨拶して」と依頼することもできます。

音声添付をWhisperで文字起こしし、既存LLMへ利用者の発言として渡します。
LLMは`speak_reply`を選択して読み上げ文を用意し、nexa-voiceでMP3を生成します。
返信には聞き取り結果、テキストの回答、音声添付を表示します。
生成が失敗した場合はテキストの回答を残し、音声の失敗を明記します。

- 社内API: `SU_STT_URL`、`SU_TTS_URL`
- 生成方式: `SU_TTS_BACKEND=irodori-tts`（既存mlx-audio方式は実試験でGPUストリームエラー）
- 声の雰囲気: `SU_TTS_INSTRUCT`。既定は落ち着いた親しみやすい若い女性。
- `SU_TTS_SPEAKER`は対応する生成方式用。Irodoriでは声の雰囲気を使用。
- 添付8MB以下、1件ずつ。2分以内を推奨し、長さメタデータがある場合は120秒超を拒否。
- 文字起こしの待機上限120秒、音声生成180秒。読み上げ400文字まで。
- Discordの添付URLのみダウンロードし、リダイレクト不可。実際の受信量も8MBに制限。
- Botの音声には反応しない。ボイスチャンネル接続・常時録音は行わない。
- 入力音声をBotのディスクに保存しない。聞き取り結果と返答はDiscordに表示され、通常の返信監査の対象になる。

202から204のnexa-voiceで生成した挨拶をWhisperで読み戻し、期待する内容になることを確認。
実ユーザーのDiscord音声添付からの一連の動作は、利用開始後に確認が必要。

## 選定した声: D2

ユーザー選定のD2（Dの声を2.5半音上げた音声）を生成時の参照にする。
`SU_TTS_REF_AUDIO_PATH` は **nexa-voiceサーバー側** の永続ファイルを指す。
`SU_TTS_REF_TEXT` に参照音声のセリフ、`SU_TTS_SEED` に生成seedを設定できる。
202の設定は204の `/Users/buildman/service-runners/su-voice/references/su-D2.mp3` を参照する。
参照を指定した生成であり、完成した音声の再生速度を毎回変更する仕組みではない。

## ボイスチャンネルでの会話

1. 通常のボイスチャンネルに入る。
2. スーを呼べるテキストチャンネルで「@スー、今いるボイスチャンネルに来て」と依頼する。
3. 参加完了の返信後に話す。約1秒の無音で発言を区切り、Whisper → LLM → D2参照の音声生成 → Discordで再生する。
4. 「@スー、ボイスチャンネルから抜けて」、または会話中に退室を依頼する。

呼んだ本人のみ音声受信の対象。他の人も自分で参加・会話を依頼すると対象に加わる。
参加・退室と、会話の返答／無視／退室はLLMが判断し、参加先と権限はコードが検証する。
Botの音声は対象外。返答の再生中と直後は受信を休み、同時発話への割込み会話は未対応。
発言は30秒まで、待機は2件まで。直近4往復をメモリー上に保持し、退室時に破棄する。
音声ファイルや文字起こし本文は保存しない。返答失敗はVCのテキスト欄に通知する。
対象者が全員退出、10分無活動、接続エラー、Gateway更新・停止時に切断する。
更新中の通話は自動再参加しない。更新後にもう一度呼んでもらう。

実行要件: GuildVoiceStates、Botと依頼者のViewChannel/Connect/Speak、FFmpeg。
`@discordjs/voice`のDAVE対応と`opusscript`を利用する。
